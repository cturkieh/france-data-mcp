# france-data-mcp V0.4 phase 1 — Annuaire Santé Ameli (PS libéraux)

**Status** : approved by Cyril (2026-05-08), ready for implementation
**Predecessor** : V0.3.x — FINESS prospection-ready (13/13 GO Charleville audit, 24 familles, 95K rows en prod)

---

## 1. Objectif

Exposer l'**Annuaire Santé Ameli** (professionnels de santé libéraux conventionnés) dans le serveur MCP `france-data-mcp` pour permettre :

1. Une recherche par rayon géographique : "tous les médecins généralistes dans 5 km autour de ce point".
2. Un comptage par département + spécialité : "combien de cardiologues conventionnés en Ardennes (08) ?".

Critère de succès opérationnel : reproduire la densité MG/cardiologues observée à Charleville-Mézières (5 km autour de 49.7728, 4.7274) avec écart < 10 % par rapport au comptage manuel sur ameli.fr.

## 2. Scope

### In scope

- Nouvelle source : **Liste des PS de l'Annuaire santé Ameli** (CSV ~154 Mo, hebdomadaire). URL data.gouv resource id `432983b9-2e6f-473a-b35a-20403c300a5f` au 2026-05-08.
- Nouvelle table Supabase `annuaire_ameli` (schéma public, RLS anon read).
- 2 RPCs PostGIS : `ameli_in_radius`, `ameli_by_specialite_dept`.
- 2 nouveaux tools MCP : `professionnels_in_radius`, `professionnels_par_specialite_dept`.
- Workflow GitHub Actions cron hebdo (lundi 04:00 UTC).
- Géocodage **par centroïde commune** (geo.api.gouv.fr) — pas de géocodage adresse exact (volume).
- Test pyramide (unit + integration via Supabase Local Docker + smoke E2E Charleville).

### Out of scope (V0.4 phase 2+)

- **CDS — Centres de santé** (CSV séparé 3 Mo) : phase 2, mêmes RPCs.
- INSEE IRIS : phase 3.
- Géocodage adresse exact (BAN / IGN bulk) : pour mémoire, ~50m de précision contre ~3 km commune. Non bloquant pour le cas d'usage densité médicale.
- DOM widening sur la table `finess` : tâche de polish séparée.
- Identifiant unique du PS (RPPS/ADELI absent du CSV) : pas d'idempotence stricte sur les ré-ingestions, le swap atomic (drop + recreate) le contourne.

## 3. Source — format et limites

### CSV PS

- URL : `https://www.data.gouv.fr/api/1/datasets/r/432983b9-2e6f-473a-b35a-20403c300a5f`
- Format : 24 colonnes, délimiteur `;`, UTF-8 BOM, CRLF probable.
- Volume : **~462 K lignes** (≈ 154 Mo, calibration 1st prod run 2026-05-08). Sous-ensemble RPPS = PS libéraux conventionnés uniquement.
- Mention CGU obligatoire (art. L.1461-2 CSP) : "Source : Annuaire santé Ameli, Assurance Maladie. Données mises à jour le {datemaj}." → à inclure dans la description du tool MCP.

### Colonnes pertinentes

| Colonne | Usage |
|---|---|
| `ps_activite_nom`, `ps_activite_prenom`, `ps_activite_civilite` | identité |
| `ps_activite_raison_sociale` | structure d'exercice |
| `specialite_code`, `specialite_libelle` | filtre principal |
| `type_ps_code`, `type_ps_libelle` | médecin / IDE / sage-femme / pharmacien |
| `coordonnees_voie`, `coordonnees_complement`, `coordonnees_lieu_dit` | adresse libre (concaténée) |
| `coordonnees_code_postal`, `coordonnees_ville` | géocodage par commune |
| `coordonnees_num_tel` | telephone |
| `secteur_conventionnel_code`, `secteur_conventionnel_libelle` | filtre secteur 1/2/3 |
| `nature_exercice_code`, `nature_exercice_libelle` | libéral intégral / mixte / salarié |
| `option_tarifaire_code`, `option_tarifaire_libelle` | OPTAM / OPTAM-CO |
| `activite_particuliere_code`, `activite_particuliere_libelle` | sous-activité |
| `ps_activite_carte_vitale`, `ps_activite_apcv` | accepte CV / APCV |

### Pas de coordonnées GPS

Le CSV ne contient PAS de longitude/latitude. Géocodage requis côté ingestion. Choix V0.4 phase 1 : **centroïde commune** (geo.api.gouv.fr/communes). Précision moyenne ~3 km, suffisante pour analyse densité.

### Pas d'identifiant stable

Pas de RPPS / ADELI dans le CSV public. L'idempotence des ingestions repose donc uniquement sur le swap atomique (drop staging → rename), pas sur un `ON CONFLICT (rpps) DO UPDATE`. C'est cohérent avec le pattern FINESS.

### Table `annuaire_ameli`

  id BIGSERIAL PRIMARY KEY,

CREATE INDEX annuaire_ameli_geog_gist ON annuaire_ameli USING GIST (geog);
CREATE INDEX annuaire_ameli_dept_idx ON annuaire_ameli (code_departement);

### RPCs

```sql
-- Recherche par rayon
CREATE FUNCTION ameli_in_radius(
  p_lon DOUBLE PRECISION,
  p_lat DOUBLE PRECISION,
  p_radius_km DOUBLE PRECISION,
  p_specialite_codes TEXT[] DEFAULT NULL,
  p_type_ps_codes TEXT[] DEFAULT NULL,
  p_limit INT DEFAULT 200
) RETURNS TABLE (
  id BIGINT,
  nom TEXT, prenom TEXT, civilite TEXT, raison_sociale TEXT,
  specialite_code TEXT, specialite_libelle TEXT,
  type_ps_code TEXT, type_ps_libelle TEXT,
  adresse TEXT, code_postal TEXT, ville TEXT,
  code_departement TEXT, code_insee TEXT,
  secteur_conventionnel_code TEXT,
  telephone TEXT,
  distance_m DOUBLE PRECISION,
  geom JSONB
) LANGUAGE sql STABLE
AS $$
  SELECT id, nom, prenom, civilite, raison_sociale,
         specialite_code, specialite_libelle,
         type_ps_code, type_ps_libelle,
         adresse, code_postal, ville,
         code_departement, code_insee,
         secteur_conventionnel_code,
         telephone,
         ST_Distance(geog, ST_MakePoint(p_lon, p_lat)::geography) AS distance_m,
         ST_AsGeoJSON(geom)::jsonb AS geom
  FROM annuaire_ameli
  WHERE geog IS NOT NULL
    AND ST_DWithin(geog, ST_MakePoint(p_lon, p_lat)::geography, p_radius_km * 1000)
    AND (p_specialite_codes IS NULL OR specialite_code = ANY(p_specialite_codes))
    AND (p_type_ps_codes IS NULL OR type_ps_code = ANY(p_type_ps_codes))
  ORDER BY geog <-> ST_MakePoint(p_lon, p_lat)::geography
  LIMIT LEAST(p_limit, 500);
$$;

-- Comptage / liste par département + filtres
CREATE FUNCTION ameli_by_specialite_dept(
  p_departement TEXT,
  p_specialite_code TEXT DEFAULT NULL,
  p_type_ps_code TEXT DEFAULT NULL,
  p_limit INT DEFAULT 500
) RETURNS TABLE ( ... ) LANGUAGE sql STABLE AS $$ ... $$;
```

`ST_AsGeoJSON(geom)::jsonb` est obligatoire : PostgREST sérialise `geometry` brut en hex EWKB, pas en GeoJSON (lesson learned FINESS V0.2).

### RPCs staging

- `ingest_create_annuaire_ameli_staging()` : `CREATE TABLE annuaire_ameli_staging (LIKE annuaire_ameli INCLUDING DEFAULTS)` + RLS, `NOTIFY pgrst, 'reload schema'`.
- `ingest_apply_ameli_geom_batch(p_limit INT)` : si on choisit le pattern "insert sans geom, transform après". **Décision V0.4** : non — on calcule le centroïde côté client (35 K communes en mémoire) et on insère directement le `ST_SetSRID(ST_MakePoint(...))` en EWKT. Plus simple, pas de RPC geom batch.
- `ingest_atomic_swap` : générique (déjà existant), passe `p_prod_table = 'annuaire_ameli'`.

## 6. Pipeline d'ingestion

### Étapes

1. **Download** : CSV PS via `downloadCsv()` (helper shared). Cache `/tmp/ameli-ps.csv`.
2. **Pre-validate** : taille minimale 100 Mo (CSV ~154 Mo, seuil 100 Mo détecte les troncatures). Header attendu inclut `ps_activite_nom`, `specialite_code`, `coordonnees_code_postal`, `coordonnees_ville`. Délimiteur `;`.
3. **Cache communes** : un seul appel `geo.api.gouv.fr/communes?fields=code,nom,centre,codesPostaux` (~4 Mo) → Map `{ key → { codeInsee, lon, lat, codeDept } }`. Clé primaire = `${cp}_${normalize(ville)}`. Clé fallback (CP unique) = `${cp}`.
4. **Stream parse + insert** : pour chaque ligne, normaliser CP (5 premiers chars), chercher la commune (clé exacte → fallback CP), construire EWKT du centroïde, batch 500 rows → `INSERT INTO annuaire_ameli_staging`.
5. **Validate** : `MIN_ROWS = 1_000_000`, `MAX_ROWS = 2_500_000`. Skip rates : `unmatched_locality < 5 %`, `bad_dept < 1 %`. **Pas** de geom batch RPC (geom calculé client-side, déjà inséré).
6. **Atomic swap** : `ingest_atomic_swap('annuaire_ameli')`.

### Skip reasons (exhaustifs, switch typé)

- `no_identity` : `nom` ET `prenom` vides → ligne invalide.
- `no_locality` : ni CP ni ville → impossible à rattacher.
- `unmatched_locality` : CP+ville non trouvés dans le cache communes (drift INSEE / commune disparue).
- `bad_dept` : CP qui ne mappe sur aucun département valide (typage défensif).

### Seuils nommés (tunables)

```ts
const MIN_SIZE_BYTES = 100_000_000;       // 100 Mo, CSV ~154 Mo
const MIN_ROWS = 300_000;        // calibrated post-1st-prod-run (462 K observed)
const MAX_ROWS = 800_000;
const BATCH_SIZE = 500;
const UNMATCHED_LOCALITY_THRESHOLD = 0.05; // 5% — au-delà, drift INSEE suspect
const STRUCTURAL_FAIL_THRESHOLD = 0.01;    // 1% — schema CSV change
```

## 9. Risques connus & mitigations

| Risque | Probabilité | Mitigation |
|---|---|---|
| Drift CSV (renommage colonne Ameli) | Moyen | `STRUCTURAL_FAIL_THRESHOLD` + workflow ouvre une issue auto |
| Drift INSEE (nouvelles communes) | Faible | `UNMATCHED_LOCALITY_THRESHOLD` 5%, geo.api.gouv mis à jour quotidien |
| Volume Supabase free tier | Moyen | 1.5M rows ≈ 1-2 Go avec JSONB raw, free tier = 500 Mo. **Décision** : `raw JSONB` reste mais on tronque les colonnes redondantes (libelle déjà = code_libelle). Si dépassement → upgrade Pro Supabase ou drop `raw`. |
| Précision géo commune insuffisante | Faible | V0.4 phase 1 délibéré ; phase 2 = géocodage adresse exact si demande métier |
| RGPD / CNIL | Faible | Données déjà publiques (data.gouv.fr), mention CGU obligatoire affichée |
