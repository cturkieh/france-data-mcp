Faux « fermé » sur les sites de santé repris (M&A)

● Sévérité P1 — faux négatif silencieux Base V0.15.0 22 mai 2026 Document de décision — aucun code écrit

1 Résumé exécutif

verifier_site_actif et 3 autres tools déclarent « fermés » des sites en réalité actifs, dès qu'un site a changé d'exploitant (rachat / M&A). Bug confirmé et reproduit en production sur les 2 cas signalés.

Cause

Le moteur de résolution SIRET choisit le « meilleur » SIRET d'une adresse sans jamais que le statut actif ne compte.

Portée

Défaut du moteur partagé → 4 tools, toutes les familles FINESS. Structurel, pas anecdotique.

Reco

Option A correction ciblée + champ succession. Pas de migration DB.

3 Cause-racine — deux mécanismes

Le moteur produit une liste candidates[] et désigne un best_match — choisi par ressemblance d'adresse seule. Le statut actif n'entre nulle part dans la sélection.

Mécanisme A — chemin RPPS (Neuilly Sablons)

1Le moteur part des SIRET déclarés dans RPPS par les professionnels.
2Ces déclarations pointent encore vers l'ancienne société (BIO EPINE).
3DINUM ne liste que les établissements de ce SIREN → l'ancien, fermé, devient best_match.
✕Le filet géographique n'est jamais armé (il l'est seulement si best_match === null).
Conséquence Le SIRET du repreneur n'est jamais découvert — absent même de candidates[].

Mécanisme B — fallback géo (Pont de Neuilly)

1RPPS vide → le fallback géographique est armé.
2/near_point découvre bien Biogroup actif (présent dans candidates[]).
✕Tri d'adresse : « 85 AV » (fermé) score 1.00 vs « 85 AVENUE » (Biogroup) 0.94.
✕Name filter : FINESS dit encore « BIOEPINE » → Biogroup jugé « hors-sujet » et disqualifié.
Conséquence Le repreneur est vu… puis activement rejeté par deux filtres.
Défaut central Le statut actif n'est jamais un critère. La règle de succession existante n'opère que dans le fallback géo et exige le même SIREN — or un rachat = changement d'unité légale. Pire : le name filter favorise l'ancien exploitant, car FINESS conserve l'ancienne enseigne. Un commentaire du code affirme ce cas « protégé » — la prod le réfute.

4 Portée — pourquoi corriger dans le MCP

4 tools touchés — tout consommateur du moteur : verifier_site_actif · historique_etablissement · reconcilier_finess_sirene · inspect_site.

Toutes les familles consolidées : pharmacies (transferts de licence), EHPAD (Emeis, Korian, DomusVi), imagerie, cliniques MCO (Ramsay, Elsan, Vivalto), labos. Ce n'est pas un défaut « labo ».

5 Insight de conception

Le bon critère de co-localisation = la distance géographique

Le score_adresse (Dice textuel) ne discrimine pas le numéro de voie. Preuve prod : le voisin SOPHIE ALLALI au 48 av Ch. de Gaulle obtient 0.8958 — quasi aussi haut que le vrai repreneur au 85. Le Dice noie le numéro de rue dans les bigrammes communs.

Le bon juge La distance GPS point DINUM ↔ coords FINESS. Disponible (Etablissement.point via /near_point, finess.coords déjà utilisé). Vérifié prod : Biogroup au 3 R Garnier est à ~2 m du FINESS — co-localisation indiscutable. Un voisin de rue : 50–250 m. Le Dice reste un signal secondaire de repli.

8 Plan d'implémentation — Option A

Armement fallback léger
Élargir la condition : best_match === null || best_match.actif === false.
L2
