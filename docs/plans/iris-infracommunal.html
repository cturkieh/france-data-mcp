IRIS infracommunal — la démographie au grain quartier

Aujourd'hui le MCP s'arrête à la commune — trop grossier pour une décision d'implantation en ville. L'IRIS (~16 000 zones de ~2 000 hab) apporte la demande (âge, CSP, familles, revenu) au grain quartier, à croiser avec l'offre déjà en base.
cible 0.22.0 dépend de Phase A nouvelle géométrie : polygones +1 tool seulement → 32

1 Valeur métier & limite

Le cas qui rapporte Croiser demande (qui vit là : âge, revenu, familles) × offre (PS, labos, CDS déjà en base) → carte des micro-zones sous-dotées à forte demande = aide à l'implantation/ciblage urbain.
Limite honnête Valeur concentrée en zone urbaine (Paris, Lyon, Marseille, Bordeaux, IDF). En rural, 1 commune = 1 IRIS → aucun gain vs la maille commune.

4 Contrat profil_iris — consommé par GEO Intel

profil_iris(point | code_iris, rayon_km?)

Sans rayon_km → l'îlot seul sous le point (~2000 hab, lookup rapide). Avec rayon_km → agrégat du bassin (les îlots dont le centroïde est dans le disque) = la vraie « demande » d'une étude d'implantation.

// sortie mode bassin — la "section demande"
{
  "population_bassin": 48230,           // Σ population
  "age": { "part_65_plus": 0.213,
           "part_75_plus": 0.094 },     // Σ(65+)/Σ(pop), comptes bruts
  "familles_avec_enfants": 6120,        // somme
  "csp": { "cadres": 0.18, ... },
  "revenu_median_pondere": 24800,       // PROXY — jamais "médiane du bassin"
  "nb_iris_agreges": 27,
  "couverture": { "revenu_pct_population": 0.84,
                  "iris_revenu_manquants": 4 }
}

5 3 règles d'agrégation LOAD-BEARING (responsabilité serveur MCP)

R1
Revenu = proxy, jamais médiane vraie
La médiane d'une union ≠ moyenne des médianes. On expose une moyenne pondérée population des médianes, calculée uniquement sur les îlots couverts FILOSOFI, + couverture.revenu_pct_population. Sans ce flag = biais silencieux (îlots non couverts souvent plus pauvres/riches). C'est la doctrine d'échec silencieux fermée en V0.20.2.
R2
Inclusion par centroïde, pas par intersection
Bassin = îlots dont le centroïde est dans le rayon (chaque îlot compté une fois). PAS « intersectant le disque » (qui compterait toute la population d'un îlot effleuré → surcompte de bord). Affecte population_bassin.
R3
Parts sur comptes bruts
Toute part (âge, CSP) = Σ(compte_catégorie) / Σ(compte_total), jamais une moyenne de pourcentages d'îlots. Familles/CSP en sommes absolues.
