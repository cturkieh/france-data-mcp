5Architecture — 1 brique partagée

Un seul helper resolveNomCommune() dans api/_lib/resolve-commune.ts alimente les 3 tools. Pas de duplication, sémantique cohérente, testable unitairement.

6Décisions clés (avec rationale)

1
Scope = 3 tools, pas 4

Le 4ème (densite_etablissements_sante) ne sait pas calculer par commune. Ticket V0.20 backlog.

2
Helper boundary partagé (pas un par tool)

DRY + cohérence DX LLM + testabilité. ~30 lignes par tool évitées × 3.

3
departement désambigue (combinable avec nom_commune)

Cas LLM typique « Saint-Martin (08) » → 1 appel au lieu de 2. departement sert de hint resolver, pas de scope (sauf si fourni seul).

4
Match exact case-insensitive + accents normalisés (pas de fuzzy)

Tests live : l'API gère casse + accents nativement, mais matche fuzzy Saint-Martin → Mont-Saint-Martin (bruit). Match exact post-API = comportement déterministe.

5
Pas de gestion St → Saint en V0.19.0 (YAGNI)

Si le LLM tape "St-Martin", il reçoit unknown_commune avec un hint pédagogique. Il corrigera en 1 round-trip. V0.19.1 si Sentry remonte le pain point.

6
Erreurs via RangeError(msg, { cause }) → JSON-RPC error.data

Patch 3 lignes sur api/mcp.ts:384-393 pour propager err.cause au 4ème arg de error() (déjà supporté). Test garde-fou obligatoire.

7
XOR strict introduit dans by_categorie au passage

Aujourd'hui departement + code_insee sont AND-és silencieusement. Cassure mineure documentée : le caller (s'il y en a) reçoit désormais une erreur claire.

7Forme des erreurs JSON-RPC

ambiguous_commune

// LLM tape juste "Saint-Martin" → 5 communes en France
{
  "error": {
    "code": -32602,
    "message": "Commune ambiguë : 5 communes correspondent...",
    "data": {
      "kind": "ambiguous_commune",
      "candidates": [
        {"code":"97801", "nom":"Saint-Martin", "codeDepartement":"978", "population":31160},
        {"code":"65392", "nom":"Saint-Martin", "codeDepartement":"65", "population":436},
        // ... top 10 par pop décroissante
      ],
      "total_matches": 5,
      "truncated": false
    }
  }
}

commune_not_in_department

// LLM tape "Lyon" + dept="13" → cohérence cassée, mais Lyon existe ailleurs
{
  "error": {
    "code": -32602,
    "message": "Commune 'Lyon' introuvable dans le département '13'...",
    "data": {
      "kind": "commune_not_in_department",
      "matches_in_other_dept": [
        {"code":"69123", "nom":"Lyon", "codeDepartement":"69", "population":522969}
      ]
    }
  }
}

unknown_commune (avec hint pédagogique)

// LLM tape "St-Martin" (abréviation)
{
  "error": {
    "code": -32602,
    "message": "Commune 'St-Martin' inconnue. Utiliser le nom officiel complet...",
    "data": {
      "kind": "unknown_commune",
      "input": {"nom_commune":"St-Martin"},
      "hint": "Utiliser le nom officiel complet (ex. 'Saint-Martin'). Les abréviations 'St'/'Ste' ne sont pas reconnues."
    }
  }
}
