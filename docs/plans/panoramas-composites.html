France-Data-MCP · Cadrage Phase C

Panoramas composites — une étude d'implantation en 1 round-trip

L'étude d'implantation timeout à 300 s : le LLM appelle ~15 outils en série, ~5 s d'overhead connecteur chacun. On déplace la composition dans le serveur MCP : 1 appel → ~10 requêtes parallèles internes → 1 paquet. Étude ~5 min → 30-60 s.

Pourquoi côté MCP et pas côté GEO Intel Si le panorama était du code geo-intel, il appellerait quand même les ~10 outils un par un à travers le connecteur → même overhead, zéro gain. Le seul levier est la composition server-side : 1 appel LLM → N requêtes DB internes en parallèle → 1 payload. D'où des tools MCP. (Bonus : le levier « caps stricts » est intégré — on renvoie des résumés, pas des listes brutes.)

2 Les 2 tools composites

panorama_implantation_complet(adresse|point, rayon_km=5) vague socle

~10 sous-requêtes indépendantes en parallèle → photo complète du bassin : ancrage, territoire (densités), demande (IRIS), concurrents, pourvoyeurs, prescripteurs, CDS, qualité référentiels.

enrichir_concurrents(finess[], max=3) vague enrichissement

Enquête top 3 concurrents (dépend de la liste renvoyée par le socle) : statut + équipe + historique + signal M&A + groupe parent. Cap dur à 3 (inspect_site ~7 K tokens/appel).

Net tools 32 (post-B) + 2 = 34, toujours sous les 35 de départ. Additif : aucun tool supprimé, aucun renommage → zéro breaking côté clients.

3 Contrat de sortie — le garde-fou anti-incomplétude

Deux principes : résumés (count / top-N / moyenne, pas 100 lignes brutes) et un drapeau de couverture par section qui dit franchement complet / partiel / indisponible.

Distinction de scope « demande » panorama_sante_territoire (Phase B) porte une demande commune ; le grand frère porte une demande bassin (le rayon). On garde les deux : commune = contexte, bassin = actionnable. Même agrégation centralisée (pas de double calcul).

5 Dégradation jamais silencieuse

Divergence assumée vs le petit panorama (qui rejette TOUT si une sous-requête échoue). Le petit a 4 sous-appels homogènes → un échec = panne systémique. Le grand frère a 7 sections hétérogènes sur 5 sources → une source down ne doit pas annihiler les 6 autres.

ÉchecComportement
Ancrage (géocode KO, confidence_low)Rejet total (-32602) — rien n'est possible sans le point.
Une section (ex. Ameli down)Section → "indisponible:<raison>" dans couverture, reste renvoyé + console.warn. Le LLM voit le trou et le comble via l'outil unitaire.
