Complétude territoriale & lentilles de source

● Biais silencieux d'undercount Base V0.16.0 22 mai 2026 Document de décision — aucun code écrit

1 Résumé exécutif

Le MCP enveloppe 3 sources — FINESS, Ameli, RPPS — qui ont chacune une lentille structurelle : une sélection intégrée que les tools ne déclarent pas. famille=labo ne voit que les labos autonomes et rate ~330 plateaux de biologie hospitaliers ; les tools Ameli ne voient que le libéral conventionné et ratent ~49 % de l'effectif soignant.

Le défaut

Un compte filtré-par-lentille rendu comme un compte territorial réel — sans le dire. Biais silencieux pour ARS & journalistes.

Portée

Tout tool qui compte ou cartographie par famille / spécialité. Structurel, pas anecdotique.

Plan

2 phases Transparence d'abord (déclarer la lentille), puis complétude ciblée sur chiffres mesurés.

2 Le diagnostic — la thèse des lentilles

Les 3 référentiels ont été constitués pour répondre à une question précise. Chacun ne contient donc qu'une projection de la réalité. Ces lentilles ne sont pas des bugs — ce sont des propriétés des sources. Le bug, c'est que les tools restituent le résultat filtré sans déclarer la lentille traversée.

4 Phase 1 — Transparence — actionnable maintenant

Objectif : chaque tool déclare sa lentille. Aucune donnée enrichie. Cohérent avec « le MCP juxtapose, ne résout pas ». Coût faible — dé-risque le biais silencieux immédiatement.

4.1 · Métadonnée

Champ structuré perimetre { source, lens, exclut, note } sur chaque tool de comptage/densité — lisible et restituable par le LLM caller.

4.2 · Catalogue

Corriger finess-categories.ts : codes morts (619…), reclasser 610/612 → labo, 628/629 → pharmacie. Renforcer le test invariant.

4.3 · Routage

Documenter dans les descriptions de tools : dénombrer une spécialité = RPPS ; Ameli = conventionnement / tarifs.

Pas de migration DB, pas de nouvelle ingestion. Estimation : 1 session de développement avec discipline post-fix.

5 Phase 2 — Complétude ciblée — décision sur chiffres, post-Phase 1

Reconstruire les activités secondaires là où le trou est gros et mesuré. Ce cadrage présente les routes — la décision se prend au greenlight.

Route A — couche RPPS num_finessReco v1

« Un site héberge l'activité X si ≥ N pros de type X y sont rattachés. » Couche dérivée, recalculée au cron RPPS.

  • Signal déjà en base — zéro ingestion
  • Couvre la biologie (prouvé) + imagerie + pharmacie
  • Inférentiel — seuil N à calibrer
  • num_finess rempli à 41 %
Route B — ingestion FINESS autorisationsÀ différer

Dataset officiel data.gouv « autorisations d'activités de soin », séparé du fichier des établissements.

  • Autoritaire — autorisations ARS
  • Bon pour imagerie EML, chirurgie, urgences
  • Nouvelle source = nouveau cron
  • Ne couvre PAS la biologie (régime COFRAC distinct)
Méthodologie de mesure pré-greenlight Pour chaque activité candidate : mesurer le gain (sites détectés vs count actuel), calibrer le seuil N, reporter le taux de faux positifs sur échantillon vérifié manuellement. La couche n'est exposée que pour les activités à gain net et faux positif maîtrisé.
